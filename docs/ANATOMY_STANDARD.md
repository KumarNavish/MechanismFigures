# Adapting the supplied Anatomy standard

**Source inspected:** [wheresryan22/anatomy](https://github.com/wheresryan22/anatomy), commit [`689dcf966e63d92be10a5d593c6e19e10acd4422`](https://github.com/wheresryan22/anatomy/tree/689dcf966e63d92be10a5d593c6e19e10acd4422), inspected 12 October 2026. In particular: README, SKILL, craft, verification, motion, walkthrough, kit and evaluation organization. Anatomy is Ryan's MIT-licensed project. Its code and showcase images were not copied into this skill; this document distinguishes source-derived conventions from our adaptation.

| Anatomy convention | MechanismFigures adaptation |
|---|---|
| The repository itself is the skill, with root `SKILL.md`. | One canonical root entry and relative `kit/`, `references/`, `assets/`, `scripts/`, `agents/`, `evals/`. No duplicate discoverable nested skill. |
| Standard `npx skills add … -g -a …`, Git clone and ZIP routes. | The same standard installation choices lead the README. The existing conservative Python installer remains optional for managed updates and recovery. |
| Image-led README, quick start, gallery, output modes, usage, workflow, requirements and limits. | Published calibrated figures lead; no invented demonstration replaces the twenty-reference standard or appears as a claimed skill output. |
| Truth and one explanatory object precede a parts list and geometry. | Scientific model/evidence precede a named inventory of entities, interfaces, constraints and operations. A valid scientific space can be the object. |
| Readouts, motion and geometry share a model. | Pure state → geometry/labels/readout, with time and intervention semantics made explicit. |
| Kit, long-form references and executable verification support the skill. | A small original evidence-linked SVG/geometry kit, model-driven playback helper, local 1×/4× capture, and scoped guides supplement the existing review tools. |
| Inspect actual renders and close-ups; repair faults, not audit keys. | Read every captured PNG and inspect decisive interfaces, correspondence, evidence and final-size readability before the unchanged demanding rubric. |
| Examples and evaluation prompts make expected behavior concrete. | Real published case readings remain the positive examples; test-only fixtures and explicit evaluation tasks exercise the code without pretending to be high-quality scientific results. |

## Deliberate differences

Anatomy specializes in detailed physical/isometric instruments and prescribes a dense parts inventory. Scientific mechanisms can instead require exact planar comparison, fields, topology, anatomy, a phase space or a geometric invariant. We do not impose a minimum of forty parts, isometry, framing cards, idle animation, dark mode, empty-space filling or mechanical metaphors. Those would conflict with the user's requirements whenever they obscure the mechanism or add irrelevant detail.

Anatomy's 3D, WebGL and collision-audit implementations are not claimed as capabilities of this repository. Our kit's checks are intentionally bounded; complex rendering uses the project's existing tools. We also do not copy instructions to relax a host's sandbox. Model calls and account-wide installation remain outside the installer's authority.

## Compatibility

The twenty-reference selection, all twenty-nine image bytes and evidence/quality rules are unchanged in this revision. Old website gallery and motion links redirect to their new root-asset locations while preserving query and fragment. Existing Python-managed installations can update through their original installer; installations owned by another tool must not be silently overwritten or adopted.

This adaptation is not an endorsement from Anatomy and not evidence of equal output quality. Cross-agent reliability still requires the independent evaluation protocol.
